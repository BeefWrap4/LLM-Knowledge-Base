# 章节叙事与格式规范

本规范适用于根目录 `01_*.md` 至 `54_*.md`。目标是在不削弱技术深度的前提下，让读者始终知道：
当前在解决什么问题、需要哪些前置知识、应该先掌握什么、如何动手验证，以及面试时如何表达。

## 1. 读者与叙事原则

- 默认读者具备基础编程能力，但不假设已经熟悉当前章节的专业术语。
- 先给问题、结论和最小心智模型，再进入公式、实现细节和扩展技术。
- 每个重要概念都回答四个问题：它解决什么问题、如何工作、何时使用、何时不应使用。
- 教程、工程步骤、参考信息和原理解释可以出现在同一章，但必须通过标题和过渡语明确区分。
- 保留技术边界和失败条件，不用“必然”“完全解决”“固定提升”等无条件结论。
- 版本、价格、法规、模型能力和 benchmark 必须给出核验日期或测试条件。

## 2. 章节固定结构

每章按照以下顺序组织；没有独立代码的章节也要说明验收方式，但不得保留空栏目。

1. YAML frontmatter。
2. 唯一 H1 标题。
3. `> [!abstract] 本章导航`：定位、先修、学习目标、建议路径、配套代码。
4. 导入段：用一个真实问题或工程场景说明为什么要学习本章。
5. 编号正文：由直觉到原理、由最小示例到工程实践、由正常路径到失败边界。
6. `## 🧭 本章小结`。
7. `## ✅ 自测与练习`。
8. `## 🧪 配套代码与验收`。
9. `## 🎯 面试题精讲`。
10. `## 📋 本章速查表`。
11. 可选的 `## 🗺️ 知识地图`。
12. `## 🔗 相关章节`。
13. `## 📖 一手参考资料`。

## 3. 本章导航格式

导航卡必须放在 H1 后、正文前，并包含以下字段：

```markdown
> [!abstract] 本章导航
> **定位**：说明本章在全书知识链中的作用。
>
> **先修**：[[前置章节]]；没有先修时写“无硬性先修”。
>
> **学习目标**：
> - 使用可验证的动词描述目标。
> - 每章保持 3 项，覆盖理解、应用和判断。
>
> **建议路径**：先建立直觉，再完成最小示例，最后学习工程边界与面试表达。
>
> **配套代码**：`code/chNN_topic/`；没有目录时说明替代验收方式。
```

学习目标使用“解释、实现、比较、诊断、设计、评估”等动词，避免“了解、熟悉”这类无法验收的表述。

## 4. 正文叙事单元

一个核心知识点优先采用以下微型结构：

1. **问题**：先说明现有方法的限制或实际需求。
2. **直觉**：用一句话、一个小例子或一张图建立心智模型。
3. **机制**：解释数据流、状态变化、公式或复杂度。
4. **示例**：给出可跟随的 worked example，并说明关键决策。
5. **工程化**：补充配置、指标、监控、恢复和成本。
6. **边界**：列出常见误区、失败模式和不适用场景。
7. **面试表达**：把原理、证据和取舍组织成可复述答案。

相邻小节之间增加必要的承接句，说明上一节得到什么结论、下一节为什么自然出现。不要用重复标题代替过渡。

## 5. 章节类型的侧重点

| 类型 | 主要叙事路线 |
|---|---|
| Python / 机器学习基础 | 概念 → 最小代码 → 执行过程 → 易错点 → 练习 |
| 数学 / 模型原理 | 问题 → 直觉 → 公式 → 张量形状 → 代码验证 → 边界 |
| RAG / Agent / LLMOps | 业务场景 → 架构 → 数据流 → 最小闭环 → 评测 → 故障恢复 |
| 框架 / 工具 | 定位 → 版本边界 → 核心抽象 → 最小运行 → 生产配置 → 选型 |
| 训练 / 推理 / 分布式系统 | 性能瓶颈 → 系统机制 → 指标与公式 → 工程权衡 → 压测诊断 |
| 前沿研究 | 问题定义 → 技术演进 → 论文机制 → 证据成熟度 → 工程可用边界 |
| 面试实战 | 岗位信号 → 项目证据 → 回答框架 → 深挖追问 → 模拟练习 |

## 6. 标题与层级

- 每章只能有一个 H1；H2、H3、H4 不得跳级。
- 正文 H2 使用连续的 `章号.序号`；H3/H4 可直接使用描述性标题，需要编号时必须继承父级编号。
- 固定结尾栏目不编号，统一使用本规范定义的图标和名称。
- 标题使用能说明内容的名词短语或动作短语，不使用“其他”“补充”“更多”等模糊名称。
- Emoji 只用于固定功能栏目；星级只表示面试重要度，不同时表示难度、成熟度和推荐度。
- 标题中首次出现缩写后，紧接的首段必须给出全称或定义。

## 7. 语言与术语

- 结论优先，原因和边界随后；一段只承担一个中心观点。
- 使用自然、直接、尊重读者的语气，避免宣传口号、俚语和无证据的频率判断。
- 中文正文使用全角标点；中文与英文、数字之间保留一个半角空格。
- 产品、协议和模型名称遵循官方大小写；同一术语全书使用同一译法。
- 第一次出现专业缩写时写作“中文名（English Name，缩写）”，后文使用缩写。
- 性能结论同时说明模型、硬件、数据、并发、版本和统计口径；缺少条件时写明“需要实测”。

## 8. 代码、公式、表格和图

### 8.1 代码

- 代码块之前说明目标、环境和输入，之后说明预期输出、关键观察和常见失败。
- 可运行示例优先引用 `code/chNN_topic/`，正文只保留理解概念所需的最小片段。
- 真实 API、GPU、模型下载和付费调用必须显式标注，不得伪装成默认离线验收。
- Python 示例遵循仓库 metadata、稳定 `topic_id`、`main` guard 和输出 `OK` 的现有契约；章节号只表示当前学习顺序，不作为示例的永久身份。

### 8.2 公式

- 先说明公式回答的问题，再给公式。
- 公式后定义所有变量、单位、假设和形状；容量同时区分 GB 与 GiB。
- `\text{...}` 内的下划线必须写成 `\_`，或改用数学下标。
- 不把特定模型配置写成普遍规律。

### 8.3 表格

- 表格用于稳定的字段对比，不用大段叙事填充单元格。
- 每列有明确维度；涉及时间或版本时增加“核验日期/版本”列或就近说明。
- 表格前说明比较目的，表格后给出选择结论和适用边界。

### 8.4 Mermaid

- 图前说明读图目标，图后解释关键路径。
- 节点标签短而明确；复杂流程优先显式 `flowchart`，避免依赖阅读器特有布局。
- ReAct、工具调用和外部系统图必须保持真实执行方向，不让用户节点冒充工具执行器。

## 9. Callout 约定

| Callout | 用途 |
|---|---|
| `[!abstract]` | 本章导航或章节定位 |
| `[!note]` | 定义、背景和补充事实 |
| `[!tip]` | 可操作建议、调试技巧和面试表达 |
| `[!warning]` | 安全、成本、兼容性和常见错误 |
| `[!info]` | 版本边界、证据日期和发布状态 |

同一段信息只使用一种 callout，不用颜色或图标承担唯一语义。

## 10. 章节结尾要求

- **本章小结**：3–6 条可复述结论，不重复目录。
- **自测与练习**：至少 3 个闭卷问题，覆盖解释、应用和判断。
- **配套代码与验收**：给出目录、命令、依赖层级和成功标准。
- **面试题精讲**：问题后给回答结构、边界和可能追问，不只给定义。
- **本章速查表**：压缩结论，不引入正文未解释的新概念。
- **相关章节**：说明前后依赖关系，不只罗列链接。
- **一手参考资料**：优先官方文档、标准、原论文和官方仓库，并标注核验日期。

## 11. 验收标准

- 54 章均包含本章导航、导入段和固定结尾栏目，且顺序一致。
- 编号正文连续，固定栏目不参与编号，无重复速查表或相关章节。
- WikiLinks、Markdown 链接、公式、表格、代码围栏和 Mermaid 块全部通过仓库门禁。
- 配套代码、README 和 `00_目录索引.md` 与章节结构同步。
- 每章在 Obsidian 阅读视图检查开篇、至少一个高风险图表/公式区和章节结尾。
- 运行 `verify_all.py`、pytest、Ruff、Docker 配置检查和 GitHub CI；真实 API/GPU 仅在明确条件下验收。

## 12. 设计依据

以下材料用于确定结构和语言原则，不替代各章自己的技术来源：

- [Google developer documentation style guide：Headings and titles](https://developers.google.com/style/headings)：
  使用唯一 H1、描述性标题、连续层级，并避免空标题。
- [Google developer documentation style guide：Voice and tone](https://developers.google.com/style/tone)：
  使用直接、尊重读者的表达，避免宣传语、俚语和不必要的术语堆叠。
- [Diátaxis](https://diataxis.fr/)：区分教程、操作步骤、概念解释和参考信息的写作目的。
- [Teaching the science of learning](https://pubmed.ncbi.nlm.nih.gov/29399621/)：用具体示例、主动回忆、
  间隔练习和双重编码支持长期学习。
- [The critical role of retrieval practice in long-term retention](https://pubmed.ncbi.nlm.nih.gov/20951630/)：
  章末自测用于主动提取和迁移，而不只是重复阅读。
